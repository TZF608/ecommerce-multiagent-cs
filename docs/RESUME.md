## 推荐版（约 250 字，STAR：背景与目标 → 行动 → 结果）

**电商智能客服多智能体系统**（个人项目 · 独立开发）｜ 2026.08

技术栈：Python · LangGraph · Chroma · FastAPI

**背景与目标**
售前咨询、售后订单、投诉安抚是电商客服最耗人力的三类问题，投诉还难标准化。目标：Agent 独立消化常见咨询，投诉升级给真人处理。

**行动**
- 用 LangGraph 搭"意图路由 + 四子 Agent"状态机，按会话存记忆，能接住"刚才那款耳机"这类跨轮追问
- 官方 BM25 对中文分词失效，改用 jieba + bge 向量混合检索（RRF）；订单/物流/退款做成工具，投诉用 interrupt() 挂起转人工
- 建 100 条评测集（含错别字、口语、多轮、边界），LLM-as-judge 打分并统计成本

**结果**
- 意图 98.9%、检索召回率 98%、答案通过率 100%（均分 4.94/5）、单条成本约 $0.00077
- 消融：混合 98% > 纯向量 96% > 纯 BM25 93%；27 个单测全过；交付 CLI / Web / Docker

## 面试追问准备（和简历配套）

| 可能的追问 | 怎么答 |
|---|---|
| "98.9% 意图准确率样本够吗？" | 100 条，覆盖四类意图的典型问法 + 错别字、口语、多轮、边界；仅 1 条歧义误判（"节假日发货吗"被判成售前）。general_faq 类路由目标不唯一，按设计排除不计入 |
| "人工接管具体怎么实现的？" | 投诉分支节点调 interrupt() 挂起图执行，返回待处理提示；人工结论用 Command(resume=...) 恢复，追加成一条 AI 消息 |
| "消融实验是怎么做的？" | 同一 100 条评测集、同 TOP_K，分别跑纯向量 / 纯 BM25 / 混合三路检索。混合 98% > 向量 96% > BM25 93%，且没有"纯向量命中而混合漏掉"的条目，说明融合是纯增益 |
| "跨轮追问'那款呢'怎么接住的？" | 两层：路由层遇到短句/指代开头（保守判定，避免误伤新话题）就继承上一轮意图，并用 LLM 结合最近对话把问句改写成完整问句交给 Agent；工具层再兜底改写一次检索。单轮查询不改写，100 条评测不受影响 |
| "为什么要混合检索？" | 官方 BM25 按空格分词，中文几乎失效；jieba 补分词。向量对同义表达好但对长尾差，RRF 融合两者取并集。消融数据是支撑 |
| "成本怎么算的？" | 自定义 Callback 在每次 LLM 调用结束后累加 prompt/completion token，按模型单价估算 |
| "单元测试覆盖了什么？" | 意图路由（含异常兜底）、jieba BM25 与 RRF 融合、订单/物流/退款工具、投诉 interrupt/resume 闭环、跨轮记忆、评测集 schema。用假 LLM，离线可跑 |
| "项目里哪部分最花时间？" | 中文检索质量。从字符切块改成按 `##` 语义小节切块、换 jieba 分词，召回率从初版 83.3% 提到 98%；评测集从 30 条扩到 100 条并校准关键词也花了功夫 |
